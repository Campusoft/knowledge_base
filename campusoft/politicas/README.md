## Gobierno y control de versiones

- Cada documento identifica un ID estable, versión, fecha, estado, propietario y aprobador.
- Los cambios editoriales que no alteren requisitos pueden incrementar la versión de parche; cambios menores añaden o ajustan requisitos sin cambiar el propósito; cambios mayores alteran alcance o requisitos obligatorios. Registrar el motivo en el historial de cambios del documento.
- Al aprobar una política, completar responsable, autoridad aprobadora, fecha de aprobación, fecha de entrada en vigor y próxima revisión. La fecha de versión no equivale a fecha de aprobación.
- Las excepciones deben quedar registradas con requisito afectado, justificación, riesgo, controles compensatorios, aprobador, responsable y fecha de expiración o revisión.
- Los estándares técnicos concretan controles y las guías explican cómo aplicarlos. Ninguno debe contradecir una política aprobada.
