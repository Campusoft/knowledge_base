# Prácticas de desarrollo web

Recursos de apoyo para revisar una interfaz antes de publicar y mantener código TypeScript legible. Son listas de referencia, no sustituyen pruebas de accesibilidad, seguridad, compatibilidad ni los criterios específicos del producto.

## Lista de revisión del frontend

[Front-End Checklist](https://github.com/thedaviddias/Front-End-Checklist) reúne puntos para revisar páginas antes de producción. Adaptar la lista a las tecnologías, navegadores, accesibilidad y requisitos del proyecto.

## Código limpio en TypeScript

[Clean Code concepts adapted for TypeScript](https://github.com/labs42io/clean-code-typescript) recopila convenciones y ejemplos. Aplicar el criterio del equipo y evitar tratar preferencias de estilo como reglas universales.

## Documentación técnica

[5 Steps to Create Technical Documentation That's (Actually) Helpful](https://plan.io/blog/technical-documentation/) ofrece recomendaciones para hacer documentación técnica útil. Para decisiones y documentación de arquitectura en este repositorio, consultar [Decisiones y documentación](../decisiones-y-documentacion/README.md).

## Aplicaciones como servicio

[The Twelve-Factor App](https://12factor.net/) describe una metodología para construir aplicaciones entregadas como servicios. Evaluar cada factor según el entorno y la plataforma del sistema.
